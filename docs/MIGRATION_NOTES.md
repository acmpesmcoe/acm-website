# Migration Notes

Migration performed on 2026-07-15: consolidated three separate GitHub repos
into a single npm-workspaces monorepo.

---

## What was moved

| Original Repo | GitHub URL | Moved to | Method |
|---|---|---|---|
| `acm-backend` | `github.com/acmpesmcoe/acm-backend` | `apps/server/` | `git subtree add` |
| `acm-frontend` | `github.com/acmpesmcoe/acm-frontend` | `apps/web/` | `git subtree add` |
| `acm-admin` | `github.com/acmpesmcoe/acm-admin` | `apps/admin/` | `git subtree add` |

**Git history was fully preserved** using `git subtree add` — each original
repo's commits are present in the monorepo's history. Run
`git log --oneline --all` to see them.

---

## `dist/` and `node_modules/` removal (acm-frontend)

The `acm-frontend` repo had `dist/` (build output) and `node_modules/`
(dependency cache) committed to git. This is incorrect — these are generated
files and should never be in source control.

**What was done:**
1. Root `.gitignore` was created *before* the subtree merge, but git subtree
   still brings in tracked files regardless of `.gitignore`.
2. After the subtree merge, both directories were removed from git tracking
   with `git rm -r --cached apps/web/dist apps/web/node_modules`.
3. The actual files were deleted from disk with `Remove-Item`.
4. A commit recorded this cleanup.

The root `.gitignore` now prevents `node_modules/` and `dist/` at any depth
from ever being tracked again.

---

## Decisions made

1. **`git subtree` over plain copy** — all three repos were available locally
   with their `.git` directories, so each was added as a temporary remote and
   subtree-merged. Commit history is preserved. Temporary remotes were
   removed after the merge.

2. **Renamed frontend package** — `acm-frontend`'s `package.json` had
   `"name": "acm-website"`, which collided with the root workspace package
   name. It was renamed to `"acm-web"` (matching its `apps/web` path).

3. **Created `apps/web/.env.example`** — the original `acm-frontend` repo
   had no `.env.example`, even though the code reads `VITE_API_URL` and
   `VITE_ADMIN_URL` from `import.meta.env`. One was created during migration.

4. **Deleted per-app `.gitignore` files** — `acm-backend/.gitignore`
   (`node_modules`, `.env`, `*.log`) and `acm-admin/.gitignore`
   (`node_modules`, `dist`, `.env`, `*.log`) were fully covered by the new
   root `.gitignore` and were removed to avoid duplication.

5. **Deleted per-app `package-lock.json` files** — npm workspaces uses a
   single root-level lockfile. Per-app lockfiles were deleted; a fresh one
   is generated by running `npm install` at the root.

6. **Updated server's `CORS_ORIGINS`** — added `http://localhost:5174` (admin
   dev port) and a placeholder for the deployed admin URL, which were missing.

## Config inconsistencies found (NOT fixed — to address in a future pass)

### Dependency version mismatches
- **`lucide-react`**: `apps/web` uses `^0.383.0`, `apps/admin` uses `^1.23.0`
  — these are different major versions and may have breaking API changes.

### Tailwind config differences
- `apps/admin/tailwind.config.js` defines `accent.danger` color (`var(--c-accent-danger)`)
  that `apps/web` does not have.
- `apps/web/tailwind.config.js` defines a `grad-warm` background image that
  `apps/admin` does not have.
- These are likely intentional per-app differences, but worth noting for
  future shared config extraction.

### Google Fonts `<link>` tag differences
- `apps/web/index.html` loads Outfit weights: `300;400;500;600;700;800` and
  Plus Jakarta Sans weights: `300;400;500;600;700`.
- `apps/admin/index.html` loads Outfit weights: `400;500;600;700;800` and
  Plus Jakarta Sans weights: `400;500;600;700` (no 300 weight).
- Admin is also missing the JetBrains Mono `600` weight that web includes.

### Missing favicon in admin
- `apps/admin/index.html` has no `<link rel="icon">` tag, while the web app
  does (`acm-favicon.png`). Admin's `public/` folder has `favicon.svg` and
  `icons.svg` but neither is linked in the HTML.

### Backend CORS defaults
- `apps/server/src/app.js` line 21 hardcodes a fallback of
  `http://localhost:5173,http://localhost:5174` if `CORS_ORIGINS` is not set.
  This is fine for local dev but means the server silently works without env
  config — could mask a misconfigured deployment.

## Hardcoded URLs found in source code

These are fallback URLs in the codebase. They read from `import.meta.env`
first, so they work correctly **as long as the env variables are set**. But
the fallbacks themselves are hardcoded `localhost` URLs that would be wrong
in production.

| File | Line | Code | Issue |
|---|---|---|---|
| `apps/web/src/api/client.ts` | 3 | `import.meta.env.VITE_API_URL \|\| "http://localhost:5000/api"` | Fallback to localhost — OK for dev, breaks silently in prod if env var missing |
| `apps/web/src/components/Navbar.tsx` | 16 | `import.meta.env.VITE_ADMIN_URL \|\| "http://localhost:5173"` | Fallback points to localhost:5173 — wrong even for local dev (admin runs on 5174) |
| `apps/admin/src/api/client.ts` | 3 | `import.meta.env.VITE_API_URL \|\| "http://localhost:5000/api"` | Same as web — fallback to localhost |

> **Recommendation for a future pass:** Consider removing the `|| "..."` fallbacks
> entirely and instead throwing a clear error if `VITE_API_URL` is not set.
> This makes misconfigurations visible immediately rather than causing silent
> failures in production.
